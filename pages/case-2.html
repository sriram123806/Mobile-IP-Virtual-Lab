Case Study 02

Foreign Agent Registration Failure

Mobile IP Diagnostic Procedure & Decision Flowchart

← Back to Learning Page

Problem Description

The MN is in a foreign network but the FA does not relay its Registration Request, so the HA never learns the care-of address.

Possible Causes

  • No Agent Advertisement received by the MN
  • Authentication failure (wrong shared key / SPI)
  • FA refuses service (busy, policy, unsupported options)
  • Firewall blocks UDP port 434

Diagnostic Procedure

  1. Verify the MN receives Agent Advertisements
  2. Inspect the Registration Reply code
  3. Compare security association settings on MN, FA and HA
  4. Check that UDP port 434 is permitted

Corrective Actions

  • Fix advertisement and port reachability
  • Align authentication settings
  • Retry the registration
Expected Outcome:

The FA relays the request, the HA replies with an accepted code and a binding is created.

Decision & Troubleshooting Flowchart

Evaluate each condition sequentially. Follow Green branches when checks pass, or execute the Red corrective actions when a check fails.

DIAGNOSTIC START Foreign Agent Registration Failure
↓
CHECK 1 Does the MN receive Agent Advertisements from the FA?
NO → Enable agent advertisements on the FA or send an Agent Solicitation from the MN.
YES ↓ Condition verified. Proceed to next step.
↓
CHECK 2 Is UDP port 434 reachable between MN, FA and HA?
NO → Open UDP port 434 in firewalls along the path.
YES ↓ Condition verified. Proceed to next step.
↓
CHECK 3 Do the authentication keys and SPI match on MN and HA?
NO → Correct the shared key / SPI on both ends.
YES ↓ Condition verified. Proceed to next step.
↓
CHECK 4 Does the FA accept the request (Reply code 0 or 1)?
NO → Free FA resources or adjust FA policy, then retry registration.
YES ↓ Condition verified. Proceed to next step.
↓
FINAL RESOLUTION The FA relays the request, the HA replies with an accepted code and a binding is created.
