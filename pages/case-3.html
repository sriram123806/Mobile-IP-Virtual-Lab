Case Study 03

Encapsulation Failure at Home Agent

Mobile IP Diagnostic Procedure & Decision Flowchart

← Back to Learning Page

Problem Description

The HA intercepts the packet but cannot build or send the IP-in-IP packet, so nothing enters the tunnel.

Possible Causes

  • Packet larger than tunnel MTU with DF bit set
  • No route from HA to the care-of address
  • Tunnel interface down or not configured
  • TTL of the original datagram is 1

Diagnostic Procedure

  1. Compare inner packet size + 20 bytes with the outgoing MTU
  2. Check the HA route to the care-of address
  3. Check tunnel interface status
  4. Read the inner TTL

Corrective Actions

  • Bring up tunnel interface and routes
  • Handle MTU (fragment or ICMP feedback)
Expected Outcome:

The HA adds the outer header (protocol 4, source HA, destination CoA) and forwards the packet into the tunnel.

Decision & Troubleshooting Flowchart

Evaluate each condition sequentially. Follow Green branches when checks pass, or execute the Red corrective actions when a check fails.

DIAGNOSTIC START Encapsulation Failure at Home Agent
↓
CHECK 1 Is the inner packet TTL greater than 1?
NO → The datagram must be discarded (ICMP Time Exceeded). Fix the sender or routing loop.
YES ↓ Condition verified. Proceed to next step.
↓
CHECK 2 Is the HA tunnel interface up and configured?
NO → Create or enable the IP-in-IP tunnel interface toward the care-of address.
YES ↓ Condition verified. Proceed to next step.
↓
CHECK 3 Does the HA have a route to the care-of address?
NO → Add or correct the route to the FA network.
YES ↓ Condition verified. Proceed to next step.
↓
CHECK 4 Does inner size + 20 bytes fit the MTU (or is fragmentation allowed)?
NO → Allow fragmentation, lower MSS, or return ICMP Fragmentation Needed so the CN reduces size.
YES ↓ Condition verified. Proceed to next step.
↓
FINAL RESOLUTION The HA adds the outer header (protocol 4, source HA, destination CoA) and forwards the packet into the tunnel.
