1

What is Mobile IP?

Mobile IP (RFC 5944) is an Internet Engineering Task Force (IETF) standard communications protocol designed to allow mobile device users to move from one network to another while permanently maintaining their assigned IP address.

Real-World Analogy: Think of Mobile IP like a mail forwarding service. When you go on vacation, you do not change your permanent residential address with your bank or friends; the local postal office forwards incoming letters to your temporary hotel address.

Without Mobile IP, a node changing subnets would have to obtain a completely new IP address, which immediately terminates all active TCP connections and application sessions.

2

What is a Mobile Node (MN)?

A Mobile Node (MN) is any host or router that changes its point of attachment from one network or subnetwork to another without altering its permanent IP address.

Examples include a laptop moving from home Wi-Fi to a university campus Wi-Fi, a smartphone transitioning between cellular towers, or an avionics router on a moving aircraft.

3

What is a Correspondent Node (CN)?

A Correspondent Node (CN) is a peer entity with which a Mobile Node is communicating. The CN can be stationary (such as a remote web server, database, or streaming host) or it can also be another mobile node.

Crucially, in basic Mobile IPv4, the Correspondent Node has zero awareness of mobility. It simply addresses standard IP packets to the Mobile Node's permanent Home Address.

4

What is a Home Network?

A Home Network is the subnetwork to which the Mobile Node's permanent IP address (Home Address) logically belongs. The network prefix of the Home Address matches the network prefix of the Home Network.

Example: If the Mobile Node's Home Address is 192.168.10.50/24, its Home Network is the subnet 192.168.10.0/24 located in Kanyakumari.
5

What is a Foreign Network?

A Foreign Network (or Visited Network) is any network other than the Mobile Node's Home Network to which the MN is currently attached.

When roaming in a Foreign Network (e.g. Ooty on subnet 172.16.50.0/24), normal IP routing cannot deliver packets addressed to 192.168.10.50 directly to this network without Mobile IP intervention.

6

What is a Home Agent (HA)?

A Home Agent (HA) is a router on the Mobile Node's Home Network that serves as the mobility anchor for the Mobile Node.

Key responsibilities of the HA:

  • Maintains a Binding Cache mapping the MN's Home Address to its current Care-of Address.
  • Uses Proxy ARP to intercept packets destined for the MN while the MN is away.
  • Encapsulates incoming packets in an outer IP header and forwards them through a tunnel to the Care-of Address.
7

What is a Foreign Agent (FA)?

A Foreign Agent (FA) is a specialized router on the Foreign Network that assists the Mobile Node during its visit.

Responsibilities of the FA:

  • Broadcasts periodic Agent Advertisements so moving nodes can detect foreign networks.
  • Provides a Foreign Agent Care-of Address (FA-CoA) to visiting nodes.
  • Relays registration requests between the MN and the Home Agent.
  • Terminates the tunnel, decapsulates received packets by stripping the outer IP header, and delivers the original IP packet to the MN locally.
8

What is a Home Address?

A Home Address (HoA) is an IP address assigned to the Mobile Node that remains constant regardless of where the node attaches to the Internet.

It provides transport-layer session stability. Upper-layer protocols (TCP sockets, UDP endpoints) bind to this permanent address so connections never drop when the physical interface hops between Wi-Fi and 5G.

9

What is a Care-of Address (CoA)?

A Care-of Address (CoA) is a temporary IP address that reflects the Mobile Node's current geographical/topological point of attachment.

There are two types of Care-of Addresses:

  • Foreign Agent CoA (FA-CoA): An IP address belonging to the Foreign Agent (shared by multiple visiting nodes).
  • Co-located CoA (CCoA): A temporary IP address acquired directly by the Mobile Node via DHCP or manual configuration on the foreign subnet.
10

What is tunneling?

Tunneling is a technique where a complete packet from one protocol is encapsulated within the payload of another packet for transport across an intermediary routing infrastructure.

In Mobile IP, tunneling allows packets addressed to the Home Address to cross standard Internet routers and arrive safely at the Care-of Address in the Foreign Network.

11

What is encapsulation?

Encapsulation is the process performed by the Home Agent where the entire original IP packet is inserted into the data portion of a new outer IP packet.

+------------------------+------------------------------------+ | OUTER IP HEADER | ORIGINAL IP PACKET (PAYLOAD) | | Src: Home Agent (HA) | +----------------+--------------+ | | Dst: Care-of Addr(CoA)| | Orig IP Header | Data Payload | | | Protocol: 4 (IP-in-IP)| | Src:CN Dst:MN | "ECE Lab" | | +------------------------+--+----------------+--------------+-+

The standard encapsulation method is IP-in-IP Encapsulation (RFC 2003), where IP Protocol field is set to 4.

12

What is decapsulation?

Decapsulation is the reverse process performed at the tunnel endpoint (the Foreign Agent or co-located Mobile Node). The outer IP header is stripped off, exposing the original IP datagram in its exact initial state.

Because the outer header is discarded, the Mobile Node receives the exact packet that the Correspondent Node originally transmitted.

13

What is a Forward Tunnel?

A Forward Tunnel is a unidirectional tunnel established from the Home Agent to the Foreign Agent (or directly to the CCoA). It carries inbound packets intended for the Mobile Node while it is away from home.

This is the default mechanism demonstrated in our interactive simulation.

14

What is a Reverse Tunnel?

A Reverse Tunnel (RFC 3024) is a tunnel established from the Foreign Agent back to the Home Agent for outbound packets sent by the Mobile Node.

Why is it needed? Many modern firewalls and routers perform Ingress Filtering (RFC 2827). If a packet originating from a foreign network has a source address belonging to the Home Network, firewalls drop it as suspected IP spoofing. Reverse tunneling tunnels the packet back to the HA, allowing normal routing to the CN.

15

Why is an outer IP header added?

Intermediate Internet routers route traffic solely based on the IP destination address in the packet header.

The original packet has the Mobile Node's Home Address as its destination, which directs traffic to the Home Network. Adding an outer IP header with destination set to the Care-of Address redirects the packet physically across the Internet to the Foreign Network where the MN currently resides.

16

Why is the original IP packet preserved?

Preserving the original IP packet unchanged is fundamental to transparent mobility:

  • TCP Pseudo-Header Checksum: Transport layers calculate checksums using the original source and destination IP addresses. Modifying them in-flight would corrupt checksums and abort TCP sessions.
  • End-to-End Transparency: Neither the sender (CN) nor receiver (MN) application layers need to be modified or made aware that physical mobility occurred.
17

How does the Home Agent identify the Mobile Node's location?

The Home Agent maintains an internal table known as the Binding Cache. When the Mobile Node moves into a foreign network, it registers by sending a Registration Request via UDP port 434.

The Registration Request contains: the MN's Home Address, its current Care-of Address, and a requested Lifetime. Upon authentication, the HA updates its binding cache and replies with a Registration Reply.

18

What happens when the Mobile Node changes networks?

When the Mobile Node moves from Foreign Network A to Foreign Network B:

  1. Agent Discovery: MN listens for Agent Advertisements or sends an Agent Solicitation.
  2. Acquires New CoA: It discovers Foreign Agent B and gets a new Care-of Address.
  3. New Registration: MN sends an updated Registration Request to its Home Agent.
  4. Binding Update: The Home Agent replaces the old CoA with the new CoA in its binding table. Subsequent packets tunnel directly to Network B.
19

How does the Foreign Agent deliver the original packet?

After stripping the outer IP header, the Foreign Agent inspects the inner destination IP address (MN's Home Address). It checks its visitor list to find the Link-Layer (MAC) address of the Mobile Node registered during the initial advertisement phase.

The FA then encapsulates the packet into a Layer-2 data link frame (e.g. Ethernet / IEEE 802.11) with the MN's MAC address as the destination and sends it over the local medium.

20

What happens when the Mobile Node returns to its Home Network?

When the Mobile Node re-enters its Home Network:

  • It hears Router Advertisements from its own Home Agent and realizes it is back home.
  • It sends a Deregistration message (a Registration Request with lifetime set to 0 and CoA equal to its Home Address).
  • The Home Agent removes the binding from its cache and cancels Proxy ARP.
  • Packets destined for the MN are once again delivered directly on the local link without tunneling or encapsulation.

Mobile IP Failure Scenarios (Cases)

Interactive analysis of real-world breakdown points, packet loss causes, and protocol mitigations.

Protocol Resiliency & Diagnostics

Examine what occurs when agents, registration timers, or tunnels experience exceptions during transmission.

CASE 1

Home Agent Unknown Location

Packet Dropped / ICMP
Situation A Correspondent Node sends a packet to the Mobile Node's Home Address, but the Home Agent has no valid Care-of Address in its Binding Cache.
What went wrong? The MN never registered, or its registration lifetime expired without renewal.
What happens to the packet? The Home Agent attempts to broadcast an ARP on the local home link. Since the MN is absent, ARP times out and the packet is dropped with an ICMP Host Unreachable returned to CN.
Why did the failure occur? Unsynchronized binding state or lost registration UDP packets.
Possible Solution: Implement periodic registration refresh with retransmission timers before the binding lifetime expires.

CASE 2

FA Registration Relay Failure

Unregistered CoA
Situation The Mobile Node arrives at a foreign network and submits a Registration Request, but the Foreign Agent fails to forward it to the Home Agent.
What went wrong? Network congestion, firewall blocking UDP port 434, or FA misconfiguration.
What happens to the packet? The Home Agent continues to forward packets to the old location or drops them. The MN cannot receive incoming communication.
Why did the failure occur? Broken intermediate path between Foreign Agent and Home Agent.
Possible Solution: MN monitors for Registration Reply with timeout fallback and requests a Co-located Care-of Address (CCoA) via DHCP instead.

CASE 3

Encapsulation Failure at HA

MTU / Buffer Drop
Situation Packet arrives at Home Agent, but adding the 20-byte outer IP header causes the datagram to exceed the Path MTU (Maximum Transmission Unit) with the Don't Fragment (DF) flag set.
What went wrong? MTU size mismatch between original link and tunneling path.
What happens to the packet? HA discards the packet and sends an ICMP "Fragmentation Needed and DF set" message back to the CN.
Why did the failure occur? Tunnel overhead (20 bytes for IPv4) exceeded path limits.
Possible Solution: Enable Path MTU Discovery (PMTUD) or implement Minimal Encapsulation (RFC 2004) which adds only 8 or 12 bytes of overhead.

CASE 4

Decapsulation Failure at FA

Header Parse Error
Situation The encapsulated packet reaches the Foreign Agent, but the FA fails to strip the outer header or recognize protocol type.
What went wrong? Checksum corruption in transit, unshared security associations, or unsupported encapsulation format (e.g. GRE instead of IP-in-IP).
What happens to the packet? Packet is silently discarded in the FA's IP stack with a decapsulation error counter incremented.
Why did the failure occur? Configuration protocol mismatch between Home Agent and Foreign Agent.
Possible Solution: Standardize tunnel negotiation parameters in the initial Registration Request / Reply exchange.

CASE 5

MN Roams Mid-Transmission

In-Flight Packet Drop
Situation The Home Agent tunnels packets to Foreign Agent A (e.g. Ooty), but the Mobile Node has just transitioned to Foreign Agent B (e.g. Coimbatore).
What went wrong? In-flight transit delay: packets were already in the network before HA received the new binding.
What happens to the packet? Foreign Agent A cannot find the MN on its local link and drops the packets.
Why did the failure occur? Handoff latency between physical link dissociation and registration completion.
Possible Solution: Implement Fast Handovers or Regional Tunneling where FA-A forwards packets to FA-B temporarily until the HA is fully synchronized.

CASE 6

Care-of Address Becomes Invalid

Routing Black Hole
Situation The Mobile Node was using a Co-located CoA obtained via DHCP, but its DHCP lease expired or the access point revoked the lease.
What went wrong? DHCP lease renewal failed due to RF interference or server timeout.
What happens to the packet? HA continues sending tunneled packets to an unallocated or reassigned IP, creating a black hole.
Why did the failure occur? Address allocation lifetime de-synchronization.
Possible Solution: Link the Mobile IP registration lifetime directly to the minimum of the DHCP lease time and the binding duration.

CASE 7

MN Returns to Home Network

Normal Direct Route
Situation The Mobile Node leaves the Foreign Network and reconnects to its physical Home Network (e.g. Kanyakumari).
What happens? MN sends a Deregistration message (Lifetime = 0). The Home Agent purges its Binding Cache and discontinues Proxy ARP.
What happens to the packet? No encapsulation occurs! Inbound packets are routed directly to the Home Network and delivered straight to the MN on the local link.
Why is this important? Eliminates unnecessary tunneling overhead and triangular routing latency while at home.
Standard Protocol Operation: This is a planned transition. Mobile IP seamlessly reverts to standard native IPv4 delivery.

CASE 8

FA Reached, But MN Unavailable

Last-Mile Loss
Situation The tunneled packet arrives at the Foreign Agent and is successfully decapsulated, but the Mobile Node has powered off or entered an RF dead zone.
What went wrong? Mobile Node battery exhaustion, sudden antenna disconnect, or deep wireless shadow.
What happens to the packet? FA broadcasts Layer-2 frames on the local medium. With zero ACK from MN, frames are dropped after maximum MAC retransmissions.
Why did the failure occur? Physical layer link loss in the wireless last-mile.
Possible Solution: Foreign Agent packet buffering combined with paging mechanisms to wake or wait for the node before dropping.
